## 🛠️ Module 1: Syntax Foundations

### 📝 01 - Comments
* **Definition**: Comments are non-executable lines of code used to document logic for developers and maintainers.
* **Detailed Types**:
    * **Single-line**: Used for brief notes. Starts with the `#` symbol.
    * **Multi-line**: Used for long documentation or "docstrings." Enclosed in triple quotes (`'''` or `"""`).
* **Real-Life Example**: Like a sticky note on a document—it provides context without changing the actual text of the document.

| Feature | Syntax | Best Use Case |
| :--- | :--- | :--- |
| Single-line | `#` | Explaining a single line of code |
| Multi-line | `'''` or `"""` | Documentation and large blocks |

---

### 🔢 02 - Type Conversion & User Input
* **Definition**:
*  **Type Conversion**:- is the process of changing data from one type (like text) to another (like numbers).
   **User Input**:- is the method of collecting data from the user at runtime.
* **Detailed Types**:
    * **Implicit Conversion**: Python automatically converts types during calculations (e.g., adding an integer to a float).
    * **Explicit Conversion (Typecasting)**: The developer manually forces a change using functions like `int()`, `float()`, or `str()`.
* **Real-Life Example**: A digital scale taking a physical weight (input) and converting it to a number on a screen (conversion).

| Type | Function | Real-World Match |
| :--- | :--- | :--- |
| Integer | `int()` | Whole numbers (e.g., age) |
| Floating | `float()` | Decimal numbers (e.g., price) |
| String | `str()` | Text data (e.g., names) |

## 🛠️ Module 2: Logic & Control Flow

### 🚦 01 - Conditional Statements
* **Definition**: These are decision-making blocks that execute specific code only if a condition is met.
* **Detailed Types**:
    * **if**: The primary condition check.
    * **elif**: Short for "else if"; checks alternative conditions if the first check fails.
    * **else**: The fallback block that runs if no previous conditions are True.
* **Real-Life Example**: A login screen—**if** the password is correct, you enter; **else**, it shows an error.

| Keyword | Purpose | Example |
| :--- | :--- | :--- |
| `if` | Primary logic | `if marks >= 90:` |
| `elif` | Secondary checks | `elif marks >= 80:` |
| `else` | Final fallback | `else: print("Fail")` |

---

### 🔄 02 - Loops (Iteration)
* **Definition**: Loops allow you to automate repetitive tasks by running code multiple times.
* **Detailed Types**:
    * **For Loop**: Best for iterating over a fixed sequence (like a list or a range).
    * **While Loop**: Repeats as long as a specified condition remains true.
* **Real-Life Example**: A **For Loop** is like a security guard checking 10 specific IDs; a **While Loop** is a guard checking IDs until the event ends.

| Loop Type | Best When... | Key Syntax |
| :--- | :--- | :--- |
| `for` | Repetitions are known | `for i in range(10):` |
| `while` | Repetitions depend on a condition | `while count < 5:` |

## 🛠️ Module 3: Data Structures

### 📦 01 - Lists and Tuples
* **Definition**: These are used to store multiple items in a single variable.
* **Detailed Types**:
    * **List (Mutable)**: Items can be added, removed, or changed after the list is created.
    * **Tuple (Immutable)**: Items cannot be changed once the tuple is defined.
* **Real-Life Example**: A **List** is like a shopping list you can edit; a **Tuple** is like a printed menu at a restaurant.

| Structure | Mutability | Symbol |
| :--- | :--- | :--- |
| List | Mutable (Changeable) | `[ ]` |
| Tuple | Immutable (Fixed) | `( )` |

---

### 🏛️ 02 - Object-Oriented Programming (OOPs)
* **Definition**: A programming paradigm based on "Objects" that represent real-world entities.
* **The 4 Pillars**:
    1.  **Inheritance**: A child class taking properties from a parent class.
    2.  **Encapsulation**: Keeping data private and safe inside a class.
    3.  **Polymorphism**: Allowing one function to take different forms.
    4.  **Abstraction**: Hiding complex internal logic and showing only the essentials.
* **Real-Life Example**: A **Class** is the blueprint for a car; an **Object** is the actual car (like a Tesla) you drive on the road.

| Pillar | Short Definition | Analogy |
| :--- | :--- | :--- |
| Inheritance | Reusing traits | Parent and Child |
| Encapsulation | Data security | A locked capsule |
| Polymorphism | Many forms | One man, many roles |
| Abstraction | Simple interface | Driving vs Engine logic |
